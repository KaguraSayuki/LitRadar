# 订阅组配置

订阅组用于在同一个文献库中追踪多个研究方向。每组可以有独立的检索式、关键词、期刊、
种子文献和排序偏好，同一篇文献仍只保存一份题录。

安装和密钥配置见 [README](../README.md)，全部画像字段见
[interests.example.yaml](../interests.example.yaml)。

## 添加分组

1. 打开网页“检索词与偏好”（`/interests`），或直接编辑项目的 `interests.yaml`。
2. 将配置整理为顶层 `groups:` 列表，在列表中为每个方向添加一项。
3. 保存配置。网页编辑器会校验 YAML 和字段类型，并在覆盖前备份原文件。
4. 刷新页面并选择分组，再到“统计”页运行检索或完整流水线；也可以使用下方的命令行。

当前通过 YAML 编辑分组，没有单独的“新增分组”按钮。配置中有至少两个组时，顶部
显示切换器；停用组仍可切换查看，并标记为已停用。新增组尚未同步或采集到文献时，
列表为空。

下面的配置包含两个研究方向。内容均为虚构占位，检索式和关键词应按自己的需求填写：

```yaml
groups:
  - slug: default
    name: 示例方向 A
    direction: 仅演示配置结构，请填写自己的研究方向。
    search_queries:
      - '"sample topic a" measurement'
    s2_queries:
      - '"sample topic a" + measurement'
    keywords:
      core: [sample topic a]
      bonus: [measurement]
    journals:
      core: []
    seed_dois: []
    llm_rank: true
    enabled: true

  - slug: example-b
    name: 示例方向 B
    direction: 第二个虚构方向，仅用于演示分组操作。
    s2_queries:
      - '"sample topic b" + analysis'
    keywords:
      core: [sample topic b, analysis]
    journals:
      core: []
    seed_dois: []
    llm_rank: false
    enabled: true
```

在项目虚拟环境中运行：

```bash
litradar ingest search --group example-b
litradar run --group example-b
```

第一条只为 `example-b` 组检索文献；第二条运行完整流水线，其中邮件和元数据补全仍为
全局阶段。使用 Semantic Scholar 检索需要在 `.env` 中配置 `S2_API_KEY`。

## 从单方向配置转换

未使用 `groups:` 的旧配置继续有效，整份配置对应固定的 `default` 组。升级数据库时，
原有条目成员、分数与分组状态也归入该组。

转换时，将原有的 `direction`、`keywords`、`journals`、检索式和其他偏好整体缩进到
第一组中，并明确写上 `slug: default`，再添加新组。只需调整结构，无需重新复制示例
中的研究内容。使用 `groups:` 后，不要在顶层继续保留单方向字段，否则校验会报错。

`slug` 是组的稳定标识，`name` 是显示名称。保留 `default` 可继续使用旧组数据；将它
改为另一个 slug 会被视为新组，旧数据仍在数据库中，但不会自动转入新组。

## 字段与开关

| 字段 | 含义 |
|---|---|
| `slug` | 唯一且稳定的组标识，用于命令、链接和数据库关联；建议显式填写 |
| `name` | 网页显示名称，可以修改 |
| `direction` | 研究方向描述，用于 LLM 精排及方向性摘要 |
| `search_queries` / `s2_queries` | 本组检索式，分别适配通用关键词检索与 Semantic Scholar 查询语法 |
| `keywords` / `journals` / `negative` | 本组的关键词、期刊偏好与排除条件 |
| `seed_dois` | 被引追踪使用的种子文献 |
| `llm_rank` | 是否进行本组 LLM 精排，默认 `true` |
| `enabled` | 是否参加默认流水线，默认 `true` |

显式 slug 支持中文和 URL 保留字符，网页链接与 Cookie 会编码处理。slug 不能包含
控制字符、无效 Unicode，UTF-8 编码长度不能超过 256 字节。省略时会从名称派生，
因此建议显式填写，以免改名影响标识。

`enabled: false` 将组从默认流水线中停用，保留历史数据。CLI 显式指定 `--group`
仍可运行配置中存在的停用组。从配置删除组也不会删除其数据库记录；恢复相同 slug
后可以继续使用这些数据。

## 共享与分组保存的内容

| 内容 | 保存范围 |
|---|---|
| 题录、原文摘要、引用数、期刊等级 | 全局共享 |
| 收藏、已读状态 | 全局共享 |
| 检索命中形成的成员关系 | 按组保存，同一篇可属于多组 |
| 规则分、BM25 分、LLM 分及推荐理由 | 按组保存 |
| 不感兴趣、规则排除状态 | 按组保存 |
| 中文标题、问题、方法、关键结果、局限 | 一份中性摘要，全局共享 |
| “对研究的用处” | 按组生成并保存 |

收件箱、搜索和排序只读取当前组的成员。X-MOL 邮件由站外订阅决定，不使用各组检索式，
因此采集到的邮件条目会加入当时所有启用的组，再由各组规则筛选。新建组不会自动获得
全部历史文献。

## 摘要更新与调用费用

规则和 BM25 在本地计算，LLM 精排和摘要生成会调用模型。`llm_rank: false` 只关闭
本组精排；只要全局 LLM 可用，摘要阶段仍可能为它生成共享摘要和方向性说明。

一次摘要运行会先合并参与组的深度摘要需求。同一篇文献只生成一份成功的共享摘要，
即使使用 `summarize --force` 也不会因属于多个组而重复生成；参与组的方向性说明
分别补齐或更新。强制重做的范围仍受时间窗、条目上限与所选组限制。

本组没有方向性说明时，页面留空，不会显示其他组的说明。旧库升级会将可确定属于
原单方向的说明迁入 `default` 组。

修改 `direction` 后，下一次流水线同步会使该组的方向性说明失效，并在后续摘要阶段
重新生成；共享中性摘要和其他组说明保留。比较采用提示词实际使用的方向文本：去除
首尾空白后的前 300 个字符。仅修改 `name` 不会触发摘要重算。修改偏好后，需要重新
运行排序，已有分数不会因保存配置而立即重算。

## 网页与多标签页操作

页面链接、反馈、撤销和流水线请求都携带当前组的 `?g=<slug>`。在另一标签页切换组后，
已有页面的操作仍作用于该页面显示的组；Cookie 只用于未指定组时的默认选择。

关闭精排或缺少密钥时，页面显示相应说明，新的排序结果标为关键词分；已启用精排但
条目缺少 LLM 评分时，页面提示结果缺失。仅修改开关不会清除既有评分，重新排序后
才会产生与新配置对应的结果。

网页手动运行的冷却时间和每日上限按组计算。检查时会包含 CLI 与定时任务的运行记录；
邮件和元数据补全的全局记录会计入每个组。限制在 Web 入口检查，CLI 不受此检查拦截，
因此它并非覆盖全部执行方式的费用上限。访问保护的详细说明见
[部署与维护](deployment.md#访问保护)。
