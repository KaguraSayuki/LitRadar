# 网页设置方案

状态：四阶段功能已实现。操作说明见 [网页设置指南](web-settings.md)，安装和已有定时器
迁移见 [部署与维护](deployment.md)。以下保留基于提交 `07a2858` 梳理的目标与验收依据。

已交付研究方向表单、版本化配置服务、一次性初始化与登录、私有凭据管理、连接测试、
查询构建和预览、阅读与期刊设置、统一运行频率限制、配置恢复及独立应用调度。
测试覆盖旧配置身份保留、并发保存、凭据刷新、只读邮箱、跨进程调度认领、重启与夏令时。
浏览器验证覆盖实际表单提交和窄屏页面。

边界：既有服务器的外部定时器需部署代理停用并确认接管，本次实现不直接修改运行实例。
不提供 OAuth2 邮箱登录、多用户账户、网页数据库迁移或证书管理。常见期刊转换支持
表单与预览，其余旧规则保留；Crossref / OpenAlex 查询受各自匹配规则限制。

## 目标

普通用户能够通过网页完成首次配置、添加研究方向、接入邮箱和数据服务、调整阅读
偏好及更新时间。用户只需理解研究需求和界面文字，无需学习 YAML、查询运算符、
正则表达式或环境变量。

安装、启动和必要的系统维护可以由具备基本操作能力的代理协助。应用启动后，日常
配置应由用户直接完成。YAML 可以继续作为内部存储或兼容格式，但不能成为完成
正常流程的必经步骤。

## 改造前的实现与缺口

| 当前实现 | 对用户的影响 | 需要的改造 |
|---|---|---|
| `/interests` 直接编辑整份 YAML | 添加一个组也要理解缩进、列表和字段名 | 分组管理页与结构化表单 |
| 研究偏好、运行配置、密钥分散在三个文件 | 用户难以判断设置入口和依赖关系 | 统一设置入口，按任务组织页面 |
| S2 检索式需要运算符 | 即使移除 YAML，用户仍需学习查询语法 | “全部包含／任意包含／排除”的条件编辑器 |
| 邮箱和 API 检查主要使用 CLI | 保存后难以判断连接是否可用 | 就地测试连接，区分未配置、连接失败和没有结果 |
| `.env` 只补充进程中缺少的值 | 更换已有密钥后，旧进程可能继续使用旧值 | 明确配置来源和刷新规则的密钥读取层 |
| `app.host/port` 不控制 Uvicorn 启动参数 | 普通输入框可能显示“已保存”却未改变服务 | 部署设置单独处理，明确是否需要重启或部署操作 |
| 定时任务由 systemd、launchd 或任务计划程序执行 | 修改网页中的时间不会改变现有调度 | 应用管理调度，兼容既有系统任务 |
| 频率限制只在 Web 入口检查 | CLI 或定时执行可以超过网页显示的次数限制 | 统一执行策略，并准确命名限制范围 |

[网页入口](../litradar/web/app.py)、[现有编辑页](../litradar/web/templates/interests.html)
以及 [部署文件](../deploy/)。

## 设置页面

主导航提供固定的“设置”入口，首次启动时进入配置向导。设置按用户要完成的任务分为
以下页面，常用项直接显示，较少调整的参数放入“高级设置”。

| 页面 | 常用操作 | 交互方式 |
|---|---|---|
| 研究方向 | 新增、重命名、复制、停用、恢复方向，调整显示顺序 | 分组卡片、明确的操作按钮 |
| 文献筛选 | 描述方向、添加关键词和排除条件、选择期刊与作者、添加种子文献 | 普通文本、标签输入、期刊列表、DOI 或论文链接粘贴 |
| 数据与邮箱 | 自定义模型连接、启用来源、填写 API 密钥、连接邮箱、导入邮件 | 模型卡片与兼容性测试、来源卡片、状态提示、密码输入、连接测试、邮件文件选择 |
| AI 与阅读 | 启用精排、选择摘要范围、设置期刊标签和阅读偏好 | 开关、选择器、带单位的数值输入 |
| 自动更新 | 选择更新时间、时区、运行范围，查看上次和下次运行 | 时间选择器、组选择、运行状态 |
| 访问与维护 | 设置或更换密码、查看版本和连接状态、恢复配置备份 | 密码表单、状态页、恢复向导 |

空库或只有一个组时也必须能直接找到“新增研究方向”。分组标识由程序生成，改名时
保持不变，不要求用户输入 slug。移除组默认表现为停用或归档并保留历史文献，永久
删除数据应当是另一个明确操作。

### 首次使用

推荐流程是：设置访问密码 → 连接所需服务 → 创建研究方向 → 预览检索结果 → 选择
更新时间。向导可以中途保存继续，清楚说明哪些可选服务尚未接入，以及当前可用的功能。

第一步建立访问保护，尤其不能让局域网中的任意访客占用尚未初始化的实例。
部署或启动程序可生成有效期有限的一次性设置链接，由代理交给用户打开；不要求用户
手工编辑口令，也不能仅依赖反向代理后的客户端地址判断是否允许初始化。

缺少 LLM 密钥时，仍可创建研究方向并使用手动配置的筛选条件。辅助生成关键词属于
可选功能，调用前显示用途；生成结果先供用户检查，不自动保存或启动付费流水线。

### 检索条件

让用户表达“必须包含哪些内容”“这些说法满足其中一个即可”“排除哪些内容”，程序
负责转成不同来源的查询。短语、条件组和多条检索式都使用可增删的表单行，不要求
用户输入 `+`、`|`、括号或引号。

用户可用中文描述研究方向。系统可在 LLM 可用时建议英文关键词与同义词，并给出
中文说明；没有 LLM 时仍能通过术语输入和条件选择完成配置。检索预览展示匹配论文，
便于发现过宽、过窄或没有结果的条件。

旧配置中的复杂查询需要保留原有语义。迁移时将能识别的表达式转换为条件树；不能
完整转换的规则保留并说明，提供逐项重建预览，不得悄悄改成简单关键词。用户不应
为了继续修改无关设置而被要求修写表达式。

### 保存反馈

保存只修改设置，不自动启动检索、精排或摘要。页面应说明实际影响，例如：

> 已保存“材料化学”的研究方向。已有文献不会立即重新评分，下次更新将使用新设置。

需要立即应用到文献时，提供独立的“更新这个方向”按钮，并说明将执行哪些阶段。
保存失败时保留用户的输入，把错误放在对应字段附近；不要只显示异常堆栈或文件语法错误。

密钥输入为空表示保持原值，清除密钥使用单独操作。网页只显示“已设置／未设置”和
测试状态，不回传原始密钥，也不将掩码写回配置。

## 配置覆盖范围

以下是实现时的字段归属清单。它面向开发者，字段名不应直接成为界面标签。

| 配置内容 | 网页中的处理方式 |
|---|---|
| 组的 `name/direction/enabled/llm_rank`、顺序 | 分组表单；slug 自动生成且稳定保存 |
| `keywords.*`、`negative`、`negative_titles`、`exclude_title_prefixes` | 关键词标签和筛选条件；区分全文包含、标题包含与标题开头 |
| `search_query/search_queries/s2_queries/s2_venue_queries` | 条件编辑器按来源生成查询，保留旧查询的独立性 |
| `journals.core/ok/issn`、`authors_watch`、`seed_dois` | 期刊偏好、作者列表、论文链接输入；ISSN 作为辅助信息 |
| `sources.*_enabled` | 各来源开关，联动显示需要的凭据和不可用原因 |
| 来源的回溯天数、年份、条目数、页数、种子数、请求间隔、`s2_venues` | 高级采集设置，标注单位、默认值及对耗时和请求量的影响 |
| `sources.mailto` | 联系邮箱 |
| `mail.mode`、账号、服务器、端口、文件夹和搜索条件 | 邮件来源表单；常见邮箱预设可减少输入，认证方式必须与实际支持一致 |
| `mail.folder/move_processed_to` | 默认使用应用管理的收件及归档位置，普通用户可选择或上传邮件；自定义服务端路径属于部署高级项 |
| `mail.imap_mark_seen` | “处理成功后标为已读”开关，解释未读邮件范围 |
| `llm.enabled` | AI 与阅读中的全局开关 |
| `llm.model/base_url/temperature/timeout/json_mode/token_limit_parameter` | 数据与邮箱中的默认模型连接，支持 OpenAI Chat Completions 兼容文本 API；保留 DeepSeek 预设 |
| `llm.rerank_batch_size/rerank_top_k/deep_summary_top_n` | 批次大小、精排范围和深度摘要篇数；说明按组计算或共享的边界 |
| `ranking.weights` | 提供默认方案，允许高级用户调整三类信号的比重，校验输入与总和 |
| `journal_rank.enabled/fields/map/aliases/max_lookups` | 选择展示项、编辑短名称和刊名别名，设置查询上限 |
| `journal_rank.map` 中的正则规则 | 常见转换提供可视化规则及样例预览；保留无法转换的旧规则，普通流程不要求填写正则 |
| `admin.guarded_stages/cooldown_seconds/daily_limit` | 哪些运行需要密码、最短间隔、每日次数；说明适用入口，不能称为货币预算上限 |
| `app.pipeline_window_days` | 文献处理范围，与采集回溯范围一起校验 |
| `app.timezone` 与新增调度配置 | 时间选择与时区；调度和页面时间必须使用同一解释方式 |
| 各类 `*_env`、`S2_API_KEY`、API 密钥、IMAP 密码、接口口令和密码哈希 | 展示服务名称和凭据状态，隐藏环境变量名；管理员密码通过专用表单生成哈希 |
| `app.host/port/db_path/interests`、`LITRADAR_CONFIG` | 显示实际部署值；修改监听或迁移数据需要独立流程，不能按普通偏好保存后立即切换 |
| `llm.provider`、`ranking.coarse_method` | 当前没有完整的多实现切换，先使用实际实现，不提供无效的下拉选项 |

所有日常功能设置都应有网页入口。证书、服务启动和数据库路径迁移涉及宿主机权限，
归入部署流程；无法由应用执行的步骤，页面应给出可直接交给代理的具体操作说明。
这类部署边界不应迫使用户回到 YAML 中修改普通设置。

## 配置读写设计

建议先保留现有文件格式与 CLI 兼容性，新增统一的设置服务，供 Web、CLI 和后台任务
共同读取。路由只处理表单与用户反馈，校验、合并、备份和刷新规则集中实现。

1. **建立配置模型。** 对所有可编辑字段校验类型、范围及跨字段关系。表单显示中文
   标签和单位；不向用户暴露数据类内部字段名。
2. **按页保存。** 提交字段更新而非覆盖整份配置，保留未在当前页面编辑的字段、其他
   组与未知扩展字段。旧单组配置首次转换时保留 `default` 的身份。
3. **检测并发修改。** 每次读取携带版本标识，保存时检查版本；另一标签页或 CLI 已
   修改配置时，提示重新载入差异，避免后提交的旧表单覆盖新值。
4. **可靠写入。** 复用原子替换和备份机制，并增加写入互斥。普通页面尽量只更新一个
   文件；首次设置分步保存并记录完成状态，不把多文件写入描述成天然原子事务。
5. **明确生效时机。** 可热更新的功能设置在保存后刷新；正在运行的任务使用开始时
   的配置与凭据快照，新任务使用新版本。需要重启或迁移的项目单独处理。

密钥需要独立的读取和写入接口。现有 `.env` 导入后滞留在 `os.environ` 的值，不能
继续作为“网页更换密钥”的实现基础。读取层应知道值来自启动环境还是应用管理的
密钥文件：前者标记为部署管理，后者可通过网页替换并在下一次调用生效。
应用管理的密钥文件使用受限权限和原子写入，不混入可导出的普通配置。

所有设置写入和连接测试都需要访问校验、同源校验及相应的管理员授权。验证与日志应
过滤凭据；备份恢复和设置导出默认不包含密钥。连接测试不应隐式采集文献或修改邮箱
状态，LLM 测试如需实际调用，应在按钮旁说明。

## 自动更新与既有部署

长期方案由应用管理更新时间，部署层只负责让任务进程常驻。需要一个明确的调度
执行者，避免多个 Web worker、重载进程或 CLI 同时注册定时任务。后台运行继续使用
现有流水线锁，并持久化调度状态，处理重启、时区变化与错过的任务。

既有 systemd、launchd 或 Windows 任务不会因网页新增时间字段而自动失效。迁移时
必须明确选择谁负责调度：应用接管后由部署流程停用原定时入口，确认完成后再启用
内部调度。无法确认时，不能依靠单实例锁掩盖两个定时器先后重复执行的问题。

该切换可以由安装或升级代理完成一次，用户后续在网页选择时间。此方案不要求当前
就修改任何已运行的服务器实例。

## 建议实施顺序与验收

按能够独立验证的行为拆分实现和提交，不将整轮界面改造压成一个大提交。

| 阶段 | 可交付结果 | 主要验收条件 |
|---|---|---|
| 1. 统一配置服务与研究方向表单 | 新增、改名、复制、停用组；关键词、期刊、作者、种子和筛选条件可编辑 | 空库可创建组；旧 `default` 数据保留；改名不换组；旧表单不覆盖另一页面或 CLI 的修改；无须 YAML |
| 2. 数据服务、邮件和首次设置 | 密钥管理、连接测试、邮箱表单、查询构建与预览、首次使用向导 | 密钥更换实际生效且不泄漏；没有模型密钥也能配置；用户不必写查询运算符或 IMAP 表达式；测试不改变邮箱状态 |
| 3. 其余运行与阅读设置 | 排序和摘要范围、期刊展示、频率限制、配置备份恢复 | 默认值清晰；旧规则无损保留；保存和执行分开；每个保存提示与实际生效范围一致 |
| 4. 应用调度与部署衔接 | 网页控制自动更新，显示上次、下次和失败原因 | 多进程和重启不重复执行；外部定时器迁移明确；时区和错过任务的行为可验证 |

总体完成标准是：给一个不懂编程的研究者一个已经启动的实例，他能通过网页完成
“连接服务 → 添加两个方向 → 查看预览 → 保存 → 自动更新”，并能自行修正错误的
邮箱或关键词。只把配置字段换成大量无解释的输入框，不算完成。
