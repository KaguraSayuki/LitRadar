# LitRadar 设计记录

本文记录主要技术选择及方案调整的原因。安装与使用见 [README](../README.md)，
模块、数据表和接口的当前行为见 [实现架构](architecture.md)。

早期方案曾包含 SciFinder KMP、专利监控及其他未落地功能。为避免将历史设想误作
使用说明，本文将其整理为决策记录，不再重复过时的配置、SQL 和部署命令。

## 目标与范围

LitRadar 服务于个人文献阅读流程：发现新论文、判断与研究方向的相关性、快速理解
主要内容，再通过阅读反馈改善后续排序。系统需要便于自托管，允许同一用户追踪多个方向。

当前范围包括订阅邮件、学术元数据 API、中文摘要和 Web 阅读界面。系统没有多用户
权限体系，也不承担论文全文下载、专利分析、自动科研结论生成或模型训练任务。

## 主要技术选择

### SQLite 与服务端页面

个人文献库的写入主要来自定时流水线和少量阅读操作。SQLite 将题录、分组关系、评分、
摘要和运行记录保存在一处，减少独立数据库服务的部署负担。WAL 与短事务支持读取和
后台处理共存，流水线锁用于避免重复运行造成外部请求竞争。

Web 使用 FastAPI、Jinja2 和原生 JavaScript。页面由服务端渲染，反馈和手动运行通过
`fetch` 完成，无需引入前端构建流程。早期考虑的 HTMX 未被采用。

### 多源发现与统一题录

订阅邮件能够提供精选条目，但覆盖范围受订阅内容限制；关键词检索扩大覆盖，被引
追踪补充词汇不同但研究关联较强的文献。因此各来源在入库后合并为共享题录，保留来源
信息，并分别记录命中的订阅组。

DOI 是主要去重标识，入库前统一格式。无 DOI 时采用归一化标题键，作为可解释且成本
较低的回退方式；当前没有实现标题、作者、年份联合的模糊消歧。

### 规则、BM25 与 LLM 排序

规则适合表达明确的排除条件和关键词偏好；BM25 提供低成本的词汇相关度；LLM 用于
结合研究背景判断内容关联，并输出理由。三者分别承担不同层次的筛选任务。

默认不在 BM25 阶段截断候选，以降低关键词信号较弱但实际相关的论文被提前排除的
可能。需要控制精排范围时，可以设置候选上限或按组关闭精排。默认权重更侧重 LLM
判断，具体值由配置决定。

精排失败时保留已成功批次，并显示结果缺失状态。未启用精排时仍提供关键词排序，
使基础阅读流程可用。当前没有向量检索或自动调整排序权重的实现。

### 共享摘要与方向性说明

同一篇论文的研究问题、方法、结果和局限通常不随用户方向变化，适合生成一份共享
摘要；“对研究的用处”依赖研究方向，需要按组保存。这样既减少重复请求，也防止某个
方向的解释被显示到另一个方向。

摘要运行先合并参与组对深度摘要的需求，再生成共享内容。原文指纹用于识别补齐或
变化的摘要；方向变化只使对应组的方向性说明失效。强制重算同样遵守按条目复用规则。

模型允许基于原文作有限概括，但推断必须标注。关键数字与原文核对，用于提示需要
复查的内容；这一检查不能保证推理、术语和结论都正确。

### 按文献和按方向区分反馈

收藏、已读是对文献本身的操作，因此全局共享。不感兴趣和规则排除描述文献与某个
方向的关系，因此按组保存。用户收藏的条目受到保护，不因后续规则变化自动隐藏。

精排使用收藏和忽略示例进行少样本校准。当前实现是将反馈加入提示词，没有自动训练
模型或持续学习参数。

### 邮件事务与恢复

邮件处理可能因解析、数据库或网络错误中断，因此保存原文与确认收信需要有明确顺序。
当前以每封邮件为事务边界，原文、条目和完成标记全部提交后，才归档或标记已读。
数据库中的未完成原文可在后续运行中重放。

TLS 校验和不执行清除操作的会话退出用于保护邮件连接及已有邮箱状态。只读采集和
连通性测试使用只读邮箱访问。当前 IMAP 登录方式为密码或授权码，尚未接入 OAuth2。

## 早期方案的调整

| 早期设想 | 当前选择与原因 |
|---|---|
| SciFinder KMP 作为主要邮件来源 | 按实际使用需求改为 X-MOL 订阅邮件，并使用对应邮件样本验证解析器 |
| Crossref 为主要发现来源 | 默认以 Semantic Scholar 查询和被引追踪发现文献；Crossref 继续用于元数据补全，关键词检索可选 |
| OpenAlex 作为默认来源 | 改为需显式配置密钥的可选来源，避免默认流程依赖未配置的访问条件 |
| 文献和专利同时支持 | 当前只实现论文流程；专利来源、专利族去重和权利要求分析均未实现 |
| 单份研究画像 | 扩展为 `groups:`，共享条目并按组保存相关度与方向性状态 |
| `profiles/default.yaml` 与 `/profile` | 内部保留 `interests.yaml`，日常使用结构化设置表单；旧编辑路由兼容 |
| 仅接口口令和运行阶段密码验证 | 增加一次性初始化与登录会话，私有文件管理密码哈希，兼容旧接口口令 |
| 系统每日定时任务 | 独立应用调度进程，网页管理时间；外部定时器须先明确交接 |
| RSS、邮件周报与手机通知 | 尚未实现；当前支持网页上传原始订阅邮件，以 Web 阅读为主 |
| 固定周报任务 | “本期精选”由 Web 按数据生成，没有独立的每周生成任务 |

## 扩展前需要解决的问题

新增来源应先验证协议和真实记录样本，再通过统一入口入库；来源声明的摘要、日期与
标识字段不能替代必要的本地校验。新增专利来源还需要单独设计专利族、法律状态和
权利要求的表示方式，不能直接沿用论文摘要流程。

若未来增加向量排序、通知或多用户功能，应明确额外服务依赖、请求成本和状态范围。
这些方向属于待评估的扩展，不是当前版本的功能承诺。
